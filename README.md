# Paper App — 自動開発の準備

会議 → 年 → 論文一覧 → 日本語の解説、という論文早読みアプリを作るための仕様と自動開発ハーネスです。**この時点ではアプリ本体・実論文データ・公開サイトはまだありません。**

ハーネスとは、AIに指示を送るだけでなく、作業範囲・残量確認・検査・レビュー・再開・終了条件を管理する実行プログラムです。`AGENTS.md` はAIが守る作業ルールで、強制的な停止や権限制限は `harness/` のプログラムが担当します。

## 動かし方

現在のWindows PCでは、インストール済みのCodex、Node.js 24、Chrome / Edgeを使います。追加ライブラリの購入・APIキー・クラウドサーバーは不要です。`npm install` も不要です。Codexは既存のChatGPTアカウントでログイン済みである必要があります。

このリポジトリをCodexのプロジェクトとして開き、次のように依頼できます。

> AGENTS.md と README.md を読み、事前検査 doctor を実行してください。通ったら、このリポジトリのハーネスで自動開発 run を開始し、終了状態と HANDOFF.md の内容を報告してください。制限を回避せず、課金・回復枠使用・公開を行わないでください。

自分で起動する場合は、このフォルダーでターミナルを開いて以下を実行します。

```powershell
node harness/cli.mjs doctor
node harness/cli.mjs run
```

起動後は **実装 → 検査 → コードレビュー → 画面・文章レビュー → 必要なら修正** を自動で行います。コード担当とレビュー担当は、同じCodexを使いながら毎回別の新しい文脈で動きます。別のAI会社との契約や、同時に多数のAgentを走らせる必要はありません。

開発はPC上のプログラムとして動きます。PCを終了・スリープすると継続できません。ターミナルを閉じずに使い、止める場合は下記の停止コマンドを使ってください。Codexチャットに単に「続けて」と書くことと、この実行プログラムを起動することは別です。

## 停止と再開

```powershell
node harness/cli.mjs status
node harness/cli.mjs stop
node harness/cli.mjs resume
```

- `status`: 保存された進捗を見る。AIは呼びません。
- `stop`: 実行中のハーネスへ停止要求を出す。通常は次の監視時に中断して保存します。
- `resume`: 同じフォルダーのチェックポイントから再開する。残量と変更内容を再確認します。

**いずれかの適用利用枠が残り5%以下なら停止**します。長い次の作業へ入らないため、新しいAIターンの開始には残り10%超を要求します。残量が不明、認証切れ、従量クレジットがあるなど費用条件を確認できない場合も停止します。

利用状況の更新通知と10秒間隔の確認を使いますが、サービス側の反映遅延や同じアカウントの別作業があるため、実際に5%になった瞬間の停止を保証するものではありません。これは**このハーネスから起動した作業**の制御であり、他のCodexチャットを止める機能ではありません。

止まったら `.harness/HANDOFF.md` に理由と次の手順が残り、`.harness/state.json` に段階・指摘・検査・候補の識別子が保存されます。チャットの記憶だけに依存しません。作成済みのアプリファイルもそのまま残ります。これらの進捗・画面証拠はGitに送りません。

利用枠の回復はユーザーが手動で行います。ハーネスは**どの無料回復枠も自動使用せず、有料追加も購入しません**。今回許可された回復枠は、確認時に2026年10月4日14:08:26 JSTまでと表示された1件です。別の回復枠や期限切れのものは使わないでください。回復後、残り10%超が確認できれば `resume` が使えます。

## いつ終わるか

合格には、必要な検査の成功、未解決のP0/P1/P2が0件、そして**変更していない同じ成果物でコード＋UIレビューが2回連続で合格**することを要求します。UI担当には実際のPC・スマホ幅の画面を見せます。P3の好みの微調整だけで延々と修正を続けません。

最大6修正サイクル、累計実行120分、1つのAIターン20分、再開を含め最大36ターンです。同じ重要な指摘が2サイクル続いた場合も止めます。上限や停滞は「合格」ではなく `needs_human` です。再開して上限を無限にリセットする仕組みにはしていません。

| 状態 | 意味と次の手順 |
| --- | --- |
| `paused` | 利用枠・通信・手動停止など。原因を解消し `resume`。 |
| `needs_human` | 上限、停滞、壊れた証拠や仕様変更など。HANDOFFをCodexに読ませ、次の範囲を相談する。 |
| `needs_data` | 機能の検査・独立レビューは合格。実論文の収集と本番の解説レビューが必要。 |

**今回の初期ハーネスは、アプリの実装・検査・改善を自動で回すものです。出版社から全論文を自動取得する工程は含みません。** データ追加・取り込みの仕組みは実装しますが、本文取得は正当なアクセスと各配信元の条件を確認する別工程です。架空データで画面を確認できても、5会議の全論文を読んだことにはしません。

## 費用・GitHub・公開

既存のChatGPT利用枠だけを使い、追加料金を伴う処理を禁止しています。APIキー方式・有料クレジットへの切り替え、購入、回復枠の使用、クラウド実行、契約変更の操作は実装していません。起動時にChatGPT認証と追加クレジット残高0を確認し、条件が合わなければ止まります。既存契約そのものの料金や端末の電気代まで無料という意味ではありません。

対象は **[YutoOzawa/paper_app](https://github.com/YutoOzawa/paper_app) だけ**です。自動ループ自体はpush・公開を行いません。後でCodexへ保存を依頼するときも、他のリポジトリを対象にしないルールを残しています。GitHub Pagesでの公開は別途選択し、自動的には有効化しません。Google Drive連携も今回は含みません。

PDF・抽出全文・紙面画像はリポジトリに保存せず、将来の公開用データは解説・書誌・根拠の位置・公式リンクを中心にします。お気に入り等は端末内保存と書き出し／読み込みを実装対象とし、端末間の自動同期とは区別します。

## 検証コマンド

```powershell
node --test tests/harness/*.test.mjs
node harness/cli.mjs smoke
node tests/harness/runtime-probe.mjs
```

最初はAIなしの停止・再開・終了条件テストです。`smoke` は既存利用枠を少量使い、限定ツールの読み取りが実際に動くか確認します。`runtime-probe` は架空の検査用画面で、制限下のテストと4種類の画面撮影を確認します。実論文の検証ではありません。

Codex更新後に `doctor` や `smoke` が失敗した場合は、回避して進めずそのエラーをCodexへ伝えてください。実験段階のapp-server機能に依存する部分があり、将来の互換性は保証できません。
