# ハーネスの実行設計

## 担当と境界

Node.jsのコントローラーがCodex app-serverを起動し、ChatGPT認証・利用枠を読み取り専用で確認します。実装、コードレビュー、UIレビューは別のephemeral threadで順番に実行します。モデルはユーザーの既存設定を使用し、標準速度とし、別のAPIプロバイダーへ切り替えません。

動的な操作は `project_list`、`project_read`、実装担当のみの `project_write`、固定の `project_checks`、検査画像だけを返す `view_evidence` です。書ける範囲は `app/`、`tests/app/`、`scripts/app/`、`docs/app/` だけです。パスの移動、隠しファイル、リンク、Windowsのデバイス名、任意のコマンド引数を拒否します。レビュー担当には書き込みツールを渡さず、サーバー側でも拒否します。

ネイティブ環境はread-onlyです。一般のシェル、ブラウザ、画像生成、プラグイン、Apps、hooks、Web検索、追加Agent、各MCPサーバーを無効にします。`code_mode_host` は動的ツールの仲介に必要なため有効です。実機検証ではこれを無効にすると動的ツールも利用できなくなりました。承認要求は許可せず停止します。

指示だけで安全を保証するものではありません。書き込み先の検査・役割別の権限・OSとNodeの制限・残量監視を組み合わせています。CodexやOS自体の不具合まで安全性を保証するものではなく、対応しない環境では停止します。

## 検査

信頼した `check-worker.mjs` を、ネットワーク禁止・`.harness/check-work/` だけ書き込み可能なCodex sandboxで実行します。最初に保護コードへの書き込みが実際に拒否されることを確認します。

現在のWindows sandboxは広い読み取り権限が必要なため、候補のNodeテストにはさらにNode 24のpermission modeを適用します。読み取りはアプリ、アプリのテスト／スクリプト、package.jsonとテスト用一時領域に限定します。書き込みは `check-work/test-temp/` だけで、子プロセスは許可しません。検査レポート・画面画像・ハーネスには書けません。

Chrome / Edgeは既定のfile origin保護を維持し、`--allow-file-access-from-files` や `--disable-web-security` を付けません。Windowsの二重の制限でブラウザが起動できないため、`--no-sandbox` は先述の検証済みCodex OS sandbox内だけで使います。外側のネットワーク禁止・書き込み制限は維持し、制限なしのホストでは使いません。QA画面はclassic script等でfile URLでも動く必要があります。PC3画面＋狭い幅の1画面を撮り、UI担当には4枚すべてを取得させ、未確認なら合格を受け入れません。

検査用データは本番データから分離します。現在の固定検査は構文・動作テスト・容量・マニフェストの基本整合・描画の存在を扱います。全仕様の確認には独立レビューも必要です。実データの出典や科学的内容を、形式検査やモデル同士の合意だけで証明したとは扱いません。

## 保存と停止

- `.harness/state.json`: 原子的に置換する主チェックポイント。
- `.harness/HANDOFF.md`: 人間向けの停止理由・次の手順。
- `.harness/run.lock`: 二重起動を防止。生存するプロセスのロックは奪わない。
- `.harness/check-work/`: 最新の検査結果・画面・一時領域。
- `.harness/STOP`: 手動停止要求。

`.harness/` はGit対象外です。検査結果、実装ファイル、保護コードのハッシュを記録し、再開時の外部変更は自動上書きせず停止します。予期しない電源断の直前にファイル置換と状態保存がずれた場合も、勝手に進めず変更を検出して人間確認へ回します。

各段階、ファイル保存時、残量確認時にチェックポイントを書きます。5%以下、不明な残量、通信失敗時は新規作業を始めません。進行中のターンはinterruptし、実行中の検査にも中断を伝えます。引き継ぎの保存はAIを使わず行います。

監視はサービスの通知と10秒間隔です。通信のタイムアウトやサーバー側の遅延があるため、厳密な瞬間検知ではありません。10%超の開始余裕も併用します。アカウントを他の処理と共有すると、その消費も残量に影響します。

上限は再開しても持ち越します。利用枠停止は再開できますが、停滞・上限・保護ファイル変更の停止は人間による原因確認が必要です。完了済みのチェックポイントを黙って新規作業で上書きするコマンドはありません。

## 終了判定

同じ候補に対し、固定検査に合格し、別文脈のコード／UIレビューが2回連続で合格すると、機能実装確認フラグを立てて `needs_data` で終了します。実論文の本文収集・根拠検証・実際の文章レビューは後の工程です。現行ランナーがコーパス完成や公開まで自動宣言する経路はありません。

重要な未解決指摘は要件・ファイルを基準に比較し、言い換えで進捗を装わないようにします。2サイクル続けば停止します。最大6サイクル、累計120分、1ターン20分、1ターン100ツール呼び出し、再開込み36ターンを超えません。

## 現在の対象環境と公式資料

2026年10月4日のWindows環境、Node 24.19.0、Codex 0.158.0-alpha.2.1を対象に検証しています。Mac/Linuxへの移植や他バージョンの互換性検証は未実施です。必要なバイナリを自動購入・インストールしません。

- [Codex app-server公式資料](https://learn.chatgpt.com/docs/app-server): 動的ツール、利用状況、thread/turn、interrupt。
- [権限プロファイル公式資料](https://learn.chatgpt.com/docs/permissions): ファイルとネットワークの実行制限。
- [AGENTS.md公式資料](https://learn.chatgpt.com/docs/agent-configuration/agents-md): リポジトリの作業指示。

環境のログイン情報や設定内容そのものをレポートに保存しません。必要な残量、段階、指摘、検査結果だけを保存します。停止の通知先は起動したターミナルとHANDOFFです。メール・常駐通知・期限での自動再開は設定しません。
